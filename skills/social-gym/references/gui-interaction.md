# GUI Interaction Contract

Codex GUI 会话的交互层契约。SKILL.md 只做路由，本文件定义状态、控制命令、Quick Start 和分层输出规则。

## 会话状态

任一时刻会话处于且仅处于一个状态：

- `ROLE` — 正在角色扮演，assistant 以模拟人物身份回应。
- `COACH` — 教练层活动：提示、指导、复盘片段，或处理控制命令。
- `REVIEW` — 会话末复盘 + retry 入口；完成后回到 `ROLE` 或进入 `COMPLETE`。
- `PAUSED` — 会话挂起，等待 `继续` / `continue`。
- `COMPLETE` — 会话结束，可以查看进度或开始新场景。

## 合法转换与不变量

```text
ROLE ──控制/求助/自然结束──▶ COACH / REVIEW / PAUSED / COMPLETE
COACH ──继续──▶ ROLE（同一节点重试或继续）
COACH ──提示结束──▶ ROLE（同一场景、同一节点）
REVIEW ──retry──▶ ROLE（同一人物、同一节点、同一已披露信息）
REVIEW ──end──▶ COMPLETE
PAUSED ──continue──▶ 进入 PAUSED 前的那个状态
PAUSED ──end──▶ COMPLETE（标记 interrupted）
```

所有转换保持以下内容不变，除非命令明确改变它：

- 人物身份（persona identity）；
- 当前节点（当前对话推进到的位置）；
- 已披露信息边界（已经对用户说过的内容）；
- 已确定的事实与情绪状态；
- 当前模式与难度。

唯一例外：`换场景` / `switch scenario` 可以改变场景与人物，但必须保持训练 focus 与模式；`更难一点` / `harder` 只提升交互约束；`不保存` / `no save` 只改变持久化行为。

## 控制命令

自然语言控制，中英文别名均可。识别到控制命令时，assistant 先进入 `COACH` 状态、用教练标签回复，再按命令行动。

| 控制 | 别名 | 行为 |
| --- | --- | --- |
| hint / 提示 | 给个提示、help | 沿提示阶梯上移一级，返回同一人物、同一节点、同一已披露信息；不推进场景 |
| pause / 暂停 | 等一下、先停 | 保存紧凑 resume summary，进入 `PAUSED`；不再生成人物台词 |
| continue / 继续 | 继续聊、接着 | 从 pause 点恢复；未 pause 时表示继续当前 `ROLE` |
| retry / 重来 | 再试一次、重新说 | 回到同一节点，保留人物与已披露信息；不生成新场景 |
| end / 结束 | 结束训练、不练了 | 进入复盘（若证据充足）或 `COMPLETE`；不强行续聊 |
| switch scenario / 换场景 | 换个场景、换个情境 | 保持 focus 与模式，换 setting / persona / 节点 |
| harder / 更难一点 | 加大难度 | 难度升一档，只改变交互约束，不改人物敌意或身份 |
| no save / 不保存 | 这次不保存 | 当前会话全部写入被跳过，报告内存会话 |

一个 assistant 回复只处理一个控制命令。多个控制叠加时，按「状态转换 > 场景 > 难度 > 持久化」的优先级解释，并在回复里明确说明采用顺序。

## 分层输出

- `ROLE` 输出使用「角色」标签（例如 `【角色】`），纯人物台词，单场景回合。
- `COACH` / `REVIEW` 输出使用「教练」标签（例如 `【教练】`），与角色台词视觉区分；复盘、提示、控制确认都在教练层。
- 一个回复内可以包含一段角色台词 + 一段教练标签，但两个标签必须相邻且各自独立。

## ROLE 单回合约束

- 每个 `ROLE` assistant 回复只推进一个场景回合：人物说一轮、等待用户回应，不替用户说话，不连续推进两轮。
- 人物可以给出多句台词（例如同时有旁白），但整个回复只包含一轮信息推进。
- 不逐轮评价，除非用户明确要求实时教练（此时临时进入 `COACH`，随后回到 `ROLE` 同一节点）。

## Quick Start

入口不是菜单。根据用户首次意图选择以下三个概念入口之一：

1. 直接练习 — 无 profile 时进入 diagnostic 场景 1；有 profile 时选一个 focus 并立即开始匹配场景。
2. 真实场景 — 用户描述一个即将发生的场合，按 scenario-library 的真实场景 intake 提取维度，立即开始练习。
3. 进度视图 — 用户查看进度时运行 dashboard 脚本并展示结果，不自动开始新练习。

只有用户明确要求选择时才提供选项列表；否则第一个回复就是练习或进度内容。

## 歧义处理

- 控制短语与场景内容模糊（例如用户台词里正好包含“暂停”）：若在 `ROLE` 且用户没有标记为命令，优先按场景台词理解；人物可以确认“你是想暂停，还是这就是你的回应？”一次，然后按用户澄清执行。
- 会话中途改变话题：保持当前人物与节点，把话题转向当作场景内自然行为处理；若用户明说是“换场景”，再执行换场景。
- 无法识别的控制：进入 `COACH` 用一句话说明已按普通回复处理，并提供最接近的可用控制，不重置场景。

## 图像接地

用户在 `ROLE` 上传图片时，按 scenario-library 的图像接地规则使用；当前回合保持为同一节点，图片只影响场景观察，不影响已披露信息边界。`image_grounded` 作为场景标签记录，图片本身不写入 profile。
