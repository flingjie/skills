# Objection Handling

Do not counter an objection. Treat it as information about the other person's
world.

## The flow

```text
Objection
    ↓
Classify
    ↓
Understand
    ↓
Validate
    ↓
Explore
    ↓
Respond
```

## Objection types

```text
objection_type:
├── price
├── priority
├── trust
├── risk
├── timing
├── existing_solution
├── complexity
└── unclear_value
```

Classify before responding — a "price" objection and a "trust" objection need
different responses.

## Worked example

客户：

> 我们已经有自己的 Agent 平台了。

Wrong:

> 但是我们的平台更先进。

Right:

**Understand**
> 明白。你们现在的平台主要解决哪些问题？

**Explore**
> 目前使用下来，有没有哪些地方仍然比较麻烦？

**Differentiate**
> 我们做的可能不是替代整个 Agent 平台，而是解决 Agent 执行过程中的
> Observability 和 Replay 问题。

## Rules

- The first response is never a counter-argument. It is a question or a
  validation.
- "Existing solution" objections are rarely about the solution — explore what is
  still not working.
- Validate before exploring: "明白" / "理解" is not fake empathy if it is
  followed by a genuine question.
- Do not manufacture urgency to overcome an objection.

## Note on Buoyancy

Objections and rejection are expected. Buoyancy (Pink's 韧性) is the ability to
absorb a "no" without collapsing into either argument or surrender — a "no"
is a data point about their world, not a verdict about you.
